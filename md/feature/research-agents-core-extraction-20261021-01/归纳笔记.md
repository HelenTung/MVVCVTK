## 关键用户决定

- 三层协作固定为协调者、执行者、子代理。执行者采用 Codex `gpt-6.1-sol / max`，子代理采用 `gpt-6-luna / low`；项目不固定协调者模型，Claude Code 运行时适配文件保留。当前会话的模型选择不能写成长期规范。
- 下级只经项目派发平台创建，使用规定权限模式，派后核实实际配置、开启完成通知、验收后归档并确认 `archivedAt`。不得联系同级或管理非所属会话。原生派发机制禁用；本研究的累计会话预算曾获用户单独放宽，不改变规范中的默认 7 个上限。
- 派前必须先形成 DAG、依赖、角色责任和批次记录。`TASK_LOOP.md` 由协调者唯一维护；执行者提交拟派安排，确认已记入后再派发。不同物理树可并行开发同一路径的私有实现，同一物理文件和公共契约保持明确写入责任，合入同一 baseline 串行。
- 风险按实际影响判定。L0–L1 自主处理，L2 在范围内决定并事后通知，L3 依已有授权或先交用户裁决；现行规范、主干与远端操作、SDK 边界、删除等独立授权门禁仍适用。满足既有删除条件视为默认授权，检查、协调者验收和执行者删除的分工保留，不另设长期删除角色或模型例外。
- 代码、构建配置和脚本的纯注释均按只写文档类处理。新建任务记录和笔记默认不提交；本次两份收尾文件由最新明确派发要求提交，覆盖该默认值。只能由用户提供的必要事实在调研后补问，不阻塞无关工作。
- 比较双方使用相同题目、提示、模型、模式及读取方式。发现显示乱码后统一 UTF-8，并重做两侧可比输入；不能用更低的旧基准取得通过。争议题先取三次均分，只改已确认差距；Q03、Q19 后来改为各六次独立盲答、均分各至少 `7/2`，总分优势不能抵消单题未过。
- task19 的 Q19 均分 `19/6` 低于当时 `10/3` 下限，改写被拒，研究树恢复 task17。最终只采用 task21 的两题相关呈现改动；其他题是否受影响先逐题静态核对，未重测结果不得称为新实测。
- master 与 0905 使用同一最终候选；用户接受丢弃 master 六份文件共 37 处独有差异。替换时只复制到最终核实的活跃接收树 master、0905。master 原有 `.gitignore` 改动保持未提交，规范使用明确路径强制暂存。
- 替换同时关闭全局 `features.multi_agent_v2.enabled` 与 `features.multi_agent`，CLI 读回均为 false，保留原配置备份。配置变更不能证明既有会话工具已消失，新会话实际工具表仍未实测。
- 研究树、其本地分支及本任务临时材料获用户明确删除授权；两份指定备份保留。先把必要结论和协调者转移的记录留在接收树，再核对内容保存和 Git 删除条件。

## 对照方法与计分口径

共同题库为 Q01–Q28，每题 4 点，每点 0、0.5 或 1 分，满分 112。初始两侧按固定顺序分 7 组、每组 4 题；作答者只读本侧规范和指定题目，不读评分、诊断、旧答案或另一侧结果，不执行情景中的动作。模型为 `gpt-6-luna / low / full-access`。原答不因评分回写，失败与技术恢复单列。

原始基准存在读取显示风险，分数 `181/2` 仅作历史组。统一 UTF-8 后的单次基准原为 `211/2`。后续 Q05、Q06、Q08、Q09、Q10、Q11、Q24 两侧各取三次均分，其余题保留适用历史值，形成原混合基准 `310/3`。当时“差距达到 0.5 分”是协调者采用的比较口径，不能当作统计测得的稳定噪声界限。

评分审计统一更正三处历史半分：原基准 Q03 漏有界等待、UTF-8 基准 Q03 漏收尾笔记、旧候选 Q03 漏非系统盘。分别得到历史基准 90、UTF-8 单次基准 105、旧候选 `207/2`；更正只作用于仍引用该原答的分数，不能把三个半分都扣在同一个总分上。当前混合基准为 `310/3 − 1/2 = 617/6`；task17 已替换旧 Q03，仍为 `209/2`。

Q03、Q19 的评分 v2 在看到 task21 新答卷前定稿：仍按本侧合法规则评分，不要求编造未知真实负责人；Q03 接受根/子验证的合理条件说明；Q19 只在题面设定对应层级时要求完整两层转报链，但协调者派前记入的要求保留。口径澄清本身使历史分值额外变化为 0。v2 文本中的“三次”由后续明确的“每题六次”派发覆盖。

## 两题的最小复测输入

候选输入从 0905 替换提交读取，例如 `git show f2268e3a:core/LOOP.core.md`；原规范可从保留的替换前备份读取。以相同读取方式提供各自完整规范，统一 UTF-8；每题各新开六个互不继承历史的单题会话，不向作答者提供下面的评分说明。一次性收齐后用事前固定的四点评分，全数纳入均值。重新执行得到的是新样本，不能保证复现历史的逐次分数。

Q03 题面：E 是接收方实验 baseline。用户已批准本批合并及构建一个新的 SDK 发布包，但没有授权额外业务变化。现有待办：普通修复开发；独立复现；合并到 E；合并后重新生成 E 中用户打开的解决方案；合并后构建和业务回归；发行新 SDK；写回已结束目标的记录。E 中另一个会话正在运行 MSBuild。逐项说明在哪棵树进行、哪些可写 E、哪些须派生，写 E 前的检查及占用处理，SDK 发行与独立验证的树和记录差异，以及临时目录与可写产物隔离。

Q03 四点依次检查：选树及 baseline 例外；Git/进程占用检查、有界等待、写前复查和不终止他人进程；baseline 会话记录与收尾笔记，以及实际根验证、同目标子验证和只读核对的记录职责；binaryDir、生成头、测试输出、stage、clean-room、ZIP 等可写对象的隔离，TEMP/TMP 指向本树 out/tmp，非系统盘范围和只读输入共享。关键点部分正确或遗漏为半分，同一复合点不重复扣分。

Q19 题面：准备派六项任务，A 只读定位；B、C 独立只读核对；D 根据 A 的结果修改私有实现；E 根据 D 的结果做验证；F 与 D 不同目标、独立工作树，但也修改同一仓库路径。D、E 不能共用正在写入的构建目录。用户要求先记录 DAG 与批次，每批并发最多 4，记录写好前不得派发。给出 DAG、依赖来源和首批，说明提前完成、失败、方向改变时如何补位，如何处理 F 的文件重叠、构建目录及资源，能否先派后补或机械串行。

Q19 四点依次检查：`A → D → E`、B/C 独立、F 已在原始列表中，图和编号/首批一致；按本侧规则处理 D/F 跨物理树开发、单物理写者、公共契约和同 baseline 集成；构建目录独占、必要负载检查、失败依赖控制和即时动态补位；派前写入适用记录、适用记录主体、责任与并发安排。候选无额外冲突时首批可为 A/B/C/F；不得臆造 A→B 或把 F 说成后到。候选漏协调者派前记入仍扣半分，不因缺未知真实身份或题内未设定的完整两层链扣分。

完整历史题库、原答和脚本不随收尾记录搬运，依用户清理决定删除；本笔记保留两题复测输入和 28 题精确复算表，不能据此还原完整历史作答过程。
