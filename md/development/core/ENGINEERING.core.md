# 通用工程原则

> 加载范围与角色身份见 md/development/core/AGENTS.core.md 第 0 节；文件路径以规范包根为基准。参数只承接目录、格式、命令、模型和预算等具体值；本文件不要求任何特定项目架构。

## 4. 事实取证

确认实际行为时按当前源码与构建或依赖配置 → 发布脚本 → 自动化测试 → README → 规范 → 图谱或其他生成资料的顺序取证。事实与授权的区分见 md/development/core/AGENTS.core.md 第 1.2 节。

## 8. 通用修改原则

- 优先修根因，采用最小的架构改动；把改动接到现有业务链上，不另起一条平行链路。

- 不为“以后可能需要”提前加层、Manager、框架、DTO、适配器或兼容版本。

- 按 md/development/core/LOOP.core.md 第 14.1 节决定破坏性收敛后，直接删除旧入口、旧状态和旧适配，不保留 `V2`、双轨 API 或隐式 fallback。

- 优化性能前先找到真实热点和可比较的基线。

## 10. 代码、状态与生命周期

### 10.1. 通用代码要求

- 可读性优先于技巧：直接的控制流、最少的状态，不加只为形式存在的抽象。
- 不引入新的编译错误或警告；无法构建时明确说明，不用静态阅读冒充编译通过。

### 10.2. 注释说明

注释解释为什么、不变量、边界、坐标系、单位、线程和回滚，不逐行翻译代码；长流程在代码块上方用数字列出主要步骤。

### 10.3. 线程、异步与回调

- 后台任务必须有明确的 owner、有界队列、协作式取消点和有上限的期限。
- 业务期限必须有限且可取消，可使用固定时长、按实测吞吐和规模加余量推算，或进展超时；接口写明采用哪一种。停止与分离的等待期限必须是与数据量无关的固定上限；测试保护超时只按 md/development/core/TESTING.core.md 第 16.4 节处理。
- 不 detach 线程，不在错误线程上销毁受线程约束的对象。
- 新增或修改回调要写清同步返回值、拒绝时是否回调、回调线程、是否可能在发送返回前执行，以及回调中能否重入请求、查询、取消、分离和停止；具体接口族引用项目契约。
- 调用用户回调前完成内部状态转换，不持有回调可能再次获取的锁；返回后重新核验对象与版本。分离或停止失败须保留可重试的一致状态，不能谎报完成。

### 10.4. 状态、快照与几何

- 修改加载、发布、通知或刷新链前，明确唯一状态真源、候选、提交点、对外可见时机、通知顺序和失败后仍有效的状态。
- 发布前失败保持旧 active；发布成功后观察者异常不能改报为未提交。合并刷新请求不能吞掉处理过程中新到的请求，也不能持续置脏掩盖遗漏。
- 缓存和异步结果列出实际依赖与失效条件，只比较裸指针或不足范围的版本号不算有效。
- 已发布且仍有读者的快照不能原地修改，const 不等于深层不可变；借外部缓冲须说明 owner、有效期与释放顺序。
- 半开 region 与含端点 extent 不混用；维度乘积、offset、字节数在分配前检查溢出。

## 11. 风险等级

风险等级同时决定验证、独立复核和是否需要用户裁决；裁决与通知的执行规则只在 md/development/core/LOOP.core.md 第 14.1 节定义。按实际影响判级，检查措施不能改变事实风险；最高为 L3。

判级按下表的实际影响命中条件取最高等级；多分支集成按累计影响判定。影响范围、可恢复性和错误可发现性仅帮助说明实际影响，不构成独立升级条件。

| 等级 | 实际影响与例子 | 最低验证与独立复核 |
| --- | --- | --- |
| L0 不影响行为 | 文档、注释、错别字、排版，程序行为和产出不变 | 核对路径、命令和名称；纯注释逐行确认非注释内容未变；检查文件编码、换行和行尾空白 |
| L1 局部改动 | 外部依赖的契约不变，影响局限且可恢复的内部实现；修改位置或文件数量本身不决定等级 | 直接相关检查和测试，审查失败路径和无关差异 |
| L2 影响他人 | 接口、返回字段、配置格式、默认值、依赖或打包方式变化，包括破坏性接口变化与第三方依赖变化；未命中 L3 | L1 适用部分，加实际消费者与兼容、迁移检查；写明谁需要跟着改 |
| L3 牵动全局或难恢复 | 核心流程或状态机、并发与停止、难恢复的数据迁移或删除、影响权限安全或对外发布的全局变化 | L2 适用部分，加受影响的完整测试、异常、取消、回退及适用真实数据；必须由未参与实现的执行者独立复核 |

不凭行数、目录或类型名降级。缺事实时先补查，再按实际影响定级；不能仅因不确定、缺检查或增加了判级说明因子而升级，也不能以补一次检查替代应有等级。

项目只能补充具体命中条件、验证命令与专项复核触发条件，不能另造等级或降低 core 要求。缺环境、数据或权限时写明未执行项、原因与补做方式；完成声明按已有证据限缩，不能把缺检查当作低风险。

## 13. 技能与辅助资料

- skill 是可选的加速手段。只有用户指定、任务本身就是维护 skill 的产物、平台要求，或不用就拿不到必要输入时，才必须使用。用之前读 `SKILL.md`，用之后回到源码和测试核验结果。不虚构 skill 已运行，未选用的 skill 不需要说明“未使用”。

- 图谱只是辅助视图：存在且与当前分支一致时可以用来缩小阅读范围；过期或缺失时直接读源码。只有本轮任务包含图谱维护时才更新图谱。不提交 图谱机器状态目录 下的机器状态文件。

## 20. 命名语义的一般原则

- 不从单个历史反例推导新规则，也不为统一形式对全仓机械改名。

- 现有公共 API/SPI、序列化键、配置键和测试契约，不因命名规则本身单独重命名。

- 私有名称只在本来就要修改相关代码、改名能消除真实歧义、且不扩大 diff 时，才顺带收敛。

- 一个函数只表达一个动作。

- 这个对象是什么？动作有什么副作用？

- 位于哪一层，是否跨边界？

- 去掉所在的文件路径，名字是否仍然能看懂？
