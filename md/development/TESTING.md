# MVVCVTK 测试与验收规范

> 适用于 Host、仓内 Feature、已批准 SDK 产品，以及相关数据、算法、渲染、交互、线程、构建和安装测试。
>
> 本文件规定测试范围、方法和判定；架构与风险见根 `AGENTS.md`，集成流程见 `GIT_WORKFLOW.md`，Feature 契约见 `FEATURE_DEVELOPMENT.md`，正式交付见 `SDK_DELIVERY.md`。

> 通用定义按以下同号转接；本文件保留本项目的具体实施要求。

## 1. 定位、适用规则与职责边界

本节条款见以下子节。

### 1.1. 本规范解决什么

测试要让实现、执行证据和完成声明对应起来。本文细化真实数据、必要场景、结果判定和安装态验证，不另设架构、分支制度或 SDK 白名单。规则优先级与强度沿用根 `AGENTS.md` 第 1 节；具体执行范围见本文第 3.2 节。

### 1.2. 要求与实现事实分开

本文的场景按能力触发，不代表现有仓库已经支持、注册或通过这些测试。执行前从被测分支确认 API、target、preset、用例名称、输入方式和脚本参数。测试不能自行增加生产 API、公开诊断类型、第三方依赖或安装内容。SDK 的批准边界按 `SDK_DELIVERY.md` 第 2.3 节核对。

### 1.3. 文档、测试代码、数据和产物

文档维护见根 `AGENTS.md` 第 7 节，工作树用途、初始化和构建隔离见 `GIT_WORKFLOW.md` 第 2.1、2.2、2.3 节，提交权限见其第 3 节。测试使用现有 `test/`、受控数据存储和任务记录。原始输入只读共享，输出按工作树隔离；测试程序、数据、参考和日志不进入 SDK。

## 2. 基本原则与证据层次

测试要核验业务输出、状态归属和退出结果。成功 bool、退出码、文件存在和一张正常截图，都不能单独证明业务正确。

| 验证层 | 输入与环境 | 可形成的结论 | 不能替代 |
| --- | --- | --- | --- |
| 静态与构建 | 源码、CMake、工具链 | 指定范围已审查、配置或编译 | 运行正确性 |
| 单元与契约 | 解析几何、合成数据、mock、真实小输入 | 公式、不变量、边界和契约路径 | 真实工件业务 |
| 真实数据功能 | 真实小数据或真实 ROI、实际 Host/Feature | 指定样本和参数下业务通过 | 未测材料、规模或精度 |
| 组合与生命周期 | 实际组合和调度，辅以故障注入 | 指定切换、隔离与退出路径通过 | 任意组合或整卷压力 |
| 规模与性能 | 与声明匹配的真实整卷和运行环境 | 实测质量、时延、资源和稳定性 | 未测容量或硬件 |
| 安装态 SDK | 本次安装产物、真实数据、仓库外消费者 | 已覆盖的公共业务可被接收方使用 | 未交付 Feature 或完整 Qt 应用验收 |

完成声明按根 `AGENTS.md` 第 12 节区分证据层级；说明样本、必要条件、实际业务和关键结果，历史证据标明复用。

## 5. 真实数据与样本管理

本节条款见以下子节。

### 5.1. 数据分类

| 数据 | 定义 | 用途与限制 |
| --- | --- | --- |
| 真实原始输入 | 实际采集或用户、项目确认的生产输入 | 真实业务、规模与性能验收 |
| 真实小数据或 ROI | 从真实输入取得的小体数据或区域 | 日常、批量和集成回归，保留业务特征与几何 |
| 真实派生数据 | 显式重采样、量化、滤波或变换后的真实输入 | 只证明派生条件下的场景 |
| 合成与解析数据 | 程序生成的几何、噪声或填充值 | 数值、边界和解析预期 |
| 模拟与注入数据 | mock、stub、伪 runtime 或破坏副本 | 故障、拒绝和状态机路径 |

RAW/TIFF 扩展名不能证明真实。平铺、复制放大或重复运行同一 ROI，不增加独立样本数，也不能证明真实整卷扩展性。

### 5.2. 样本的必要信息

| 信息 | 实际需要的内容 |
| --- | --- |
| 业务身份 | 简短样本标识，必要时区分版本 |
| 输入解释 | 标量类型、分量、布局、dimensions/extent，适用的 endian、stride、offset |
| 几何与单位 | spacing、origin、direction、坐标系、索引定义和单位 |
| 派生关系 | 共同父样本、ROI、变换、有效区域及关键参数 |
| 比较依据 | 参考定义、指标、容差和适用限制 |

这些信息从实际输入、sidecar、配置和已有记录取得。报告规则见根 `AGENTS.md` 第 7.1 节。缺少必需几何时，阻塞依赖它的尺寸或空间结论，不能随意补 spacing=1、origin=0 或单位方向矩阵。输入疑似错配或损坏时，做针对性完整性核验。

### 5.3. 真实小数据的选取

围绕承诺选择正常结果、合法空结果、相关边界、困难区域和已修复缺陷。日常回归优先使用保留这些特征的最小真实输入，不用固定样本数代替覆盖判断。

邻域算法要保留 padding/halo，并定义有效评估区和边界条件；ROI 与整卷只在可比区域比较，不能裁掉困难部分扩大结论。同一体数据的多个 ROI 标记共同父样本。它们能扩大场景覆盖，不能当成多个独立工件。

### 5.4. ROI 几何核验

同时检查数据和几何：裁切起止索引、是否归零、spacing、direction、origin、单位、有效范围和原数据身份。

下式只适用于原点表示索引零点、ROI 新索引从零开始的契约：

```text
p(i) = o + D × (s ⊙ i)
i = a + j
o_roi = o + D × (s ⊙ a)
p_roi(j) = o_roi + D × (s ⊙ j) = p(a + j)
⊙ 表示逐分量乘法，a 是 ROI 在原索引中的起点。
```

保留绝对索引或 origin 表示 extent 起点的接口，要重新按契约推导。声明支持时覆盖非零 extent、非均匀 spacing 和非单位 direction。重标几何、插值重采样、体素裁切和显示裁切分别判定；插值后的灰度不能按无损裁切比较。

### 5.5. 存储与隔离

原始输入和参考只读共享，缓存、输出、错误副本和日志独立。真实数据不默认提交 Git、上传远端或装入 SDK；权限和敏感信息按提供方要求处理。不删除共享输入、真实数据和参考结果；唯一证据先写进测试报告或任务记录（记录方式见 `LOOP.md`）。

## 6. 参考结果、容差与结果核验

本节条款见以下子节。

### 6.1. 参考结果的来源

通用定义见 md/development/core/TESTING.core.md 第 6.1 节。

### 6.2. 按输出选择断言

| 输出 | 核验重点 |
| --- | --- |
| 加载、无损裁切、导出 | 数值、类型、顺序、几何、region、有效范围，必要时回读 |
| 分割、标签、零件 | 区域归属、体素数、连通关系、匹配和边界 |
| 表面、几何、尺寸 | 空间对应、残差分布、极值、位置、有效区和失败分类 |
| Gap 等业务结果 | 承诺字段、输入身份、合法空结果和异常语义 |
| 渲染与交互 | 目标 View、实际状态、显示、输入归属和资源恢复 |
| 异步与退出 | 接纳、终态、次数、线程、身份、期限和最终资源 |

### 6.3. 容差与指标来源

容差、误差目标、帧率、时延、内存/显存限制、重复次数和测试保护超时，都要有来源、单位或计数口径、适用范围及版本。复用需求、测试参数或配置中的单一有效来源，不按文件名或已知答案设置特例。

没有确认的数值目标时，只报告实测与限制。解析真值、离散状态、整数边界和硬件上限可以直接断言，说明契约或推导即可。

- 离散 ID、状态和原样传输的整数值精确比较。

- 浮点值预先定义绝对、相对容差和评估区；接近零、NaN、Inf 和无效样本分别判定。

- 可采用 `|actual - reference| <= atol + rtol × |reference|`，但这不是统一精度承诺。

- 标签编号不稳定时先按规则匹配区域；匹配不能掩盖合并、拆分或丢失。

- 最薄位置、阈值区和最大偏差要核验极值、位置与有效性，不能只报平均值。

- 合法无结果和失败分开；无效值不能用 0、旧值或空文件替代。

- 显示 LOD、计算分辨率和导出分辨率分别核对。

### 6.4. 请求、输入与输出绑定

结果要对应本次请求及输入身份、版本和实际依赖。改变参数、ROI、数据或几何后，确认结果刷新或明确拒绝，不能读到旧 active 或其他 Feature 的输出。缓存验证包含冷路径、有效命中和失效路径；缓存键应覆盖实际依赖。强行关闭所有缓存不能替代失效验证。

### 6.5. 算法精度研究的控制变量与独立验证

精度比较、参数选择和跨数据适用性研究，先明确**固定不变的条件**（输入、上游输出、几何、单位、参考、评估协议，以及不调整的算法和参数）与**允许变化的范围及选择规则**（候选算法、可调参数的取值范围和选择规则）。改变固定条件后重新建立可比对照。

按独立工件或扫描来源划分选参集和最终验证集；同父 ROI、重复采样和派生版本不能跨组冒充独立样本。验证集参与继续选参后，要取得新的独立证据才能作泛化结论。

数据驱动规则须事先定义、统一适用且只依赖可观察输入；参数选择和最终参数应可重放。预先确定评估集、匹配、单位、聚合和无效判定，不能减少返回点或拒绝困难点来美化误差。

按工件或父样本报告应评估点数、可比较点数、有效覆盖率，以及无效、拒绝、失败、未计算数量和原因；类别预先定义并可对账。误差、极值和尾部指标使用同一可比较集合，点数与第 17 节的用例数分开统计。

独立验证不足时可以继续探索，结论限定在已测范围，不宣称未验证的材料、工件或采集条件精度。

## 7. 用例设计与测试工程

本节条款见以下子节。

### 7.1. 用例的最小结构

通用定义见 md/development/core/TESTING.core.md 第 7.1 节。

### 7.2. 测试代码的边界

单元测试可使用获准私有边界，业务验收走实际 Host/Feature 公共入口，SDK 验收使用安装头和库。mock、故障注入和探针留在测试或私有实现中。

复用现有测试框架、目录和入口。自动化用例要实际注册，人工操作按第 7.5 节区分；命名按 `NAMING.md`，不依赖前一用例、当前目录或另一工作树产物。

#### 7.2.1. 测试目标、目录与解决方案分组

- 新用例优先进入所属模块现有 target；只有编译、链接、运行环境或隔离确有独立要求时才新建工程。

- 源码放在既有测试目录并由对应 CMake 管理，不平行新建同职责目录体系。

- 仓内测试目标设置 `FOLDER`：自动化为 `MVVCVTK/test/Automation`，手动为 `MVVCVTK/test/Manual`，支持库为 `MVVCVTK/test/Support`；沿用已有子分组。

- 在目标或现有 helper 中通过 CMake 的 `FOLDER` 属性维护分组，保持 `USE_FOLDERS` 启用；修改 CMake 后的解决方案完整性核对见 根 `AGENTS.md` 第 11.1 节。

- 物理目录、target `FOLDER`、`source_group`、CTest 名称和 `LABELS` 各司其职，分别检查。

- 遵守现有测试开关和依赖条件；支持库不注册为用例，人工程序不冒充无人值守测试，脚本不为显示分组创建空工程。

- 仅整理分组时保持名称、编译链接、默认构建、输出和安装行为；按 根 `AGENTS.md` 第 11.1 节核对解决方案完整性，并核对测试注册；本次构建和测试的最低要求按根 `AGENTS.md` 第 11 节执行。

- 需要显式提供真实数据、外部参考或其他输入才能运行的审计、性能和对照工具，可以不注册为常规 CTest 用例，但必须在 CMake 中用注释写明用途和所需输入，并按测试分组规则归组；需要它们作为证据时，按第 7.5 节记录可重放的运行过程。本次必需却没有运行的，记为 `NOT_RUN`。

### 7.3. 确定性、同步与诊断

用有界同步点和可观察阶段安排并发，不靠固定 sleep 猜交错。测试器按契约驱动 owner dispatcher、tick 或事件循环，等待设置测试保护超时及终止策略，期限按根 `AGENTS.md` 第 10.3 节区分。随机测试的 seed、实际输入和参数，以及失败时的断言差异和错误分类，写进测试报告或任务记录（记录方式见 `LOOP.md`），以便重放和定位；需要时再记录线程、请求和阶段。Debug/Release 中断言都要生效。

### 7.4. 隔离与资源约束

按 `GIT_WORKFLOW.md` 第 2.3 节隔离构建和输出。并行前检查 CPU/GPU、端口、runtime 和输出冲突，限制并发及整卷副本数。性能测量控制竞争负载，区分测试器参考副本与产品资源；安全缓存复用仍需核验输入和结果身份。

### 7.5. 自动化与人工核验

重复回归优先自动化。暂缺自动化时，可执行可重放的公共入口流程，把操作、输入、配置、断言和退出的必要证据写进测试报告或任务记录（记录方式见 `LOOP.md`）。人工视觉、参考标注和宿主操作单独统计。可实际执行的业务不因缺 CTest 入口一律判失败；公共入口不存在、无法运行或结果不可复核时，按第 17 节记录缺口。

### 7.6. 测试有效性、纠错与去重

通用定义见 md/development/core/TESTING.core.md 第 7.6 节。

纠正、合并或淘汰无新增价值的重复矩阵、仅复述 mock 值、复制实现生成预期、无依据等待及只检查非空的业务测试。头自足、链接、私有头拒绝、解析几何和命中目标的故障注入仍有各自价值。

### 7.7. 过时测试清理

通用定义见 md/development/core/TESTING.core.md 第 7.7 节。

## 8. 通用数据、几何与状态测试

| 场景 | 核验重点 |
| --- | --- |
| 正常加载及支持的布局 | 类型、维度、数值、几何、身份；endian/stride/offset 地址正确 |
| sidecar 与切片序列 | 必需元信息、顺序、缺片、损坏和不一致处理 |
| 空输入、非法尺寸和溢出 | 分配或读取前拒绝，无越界或 active 污染；极值用例不必真实分配巨大内存 |
| ROI、extent、bounds、变换 | 半开 region 与含端点 extent 分开，边界体素和物理单位正确 |
| reload 或同地址新数据 | 旧缓存和迟到结果按身份、版本及实际依赖失效 |
| 发布前失败 | 旧 active 仍有效，不暴露半成品 |
| 发布后观察者异常或重入 | 不把已提交改报未提交，旧补偿不覆盖新结果 |
| 不可变快照与借用缓冲 | 旧读者数据不被原地修改，owner、有效期和释放顺序正确 |
| 业务成功但显示失败 | 分别保留业务结果和显示状态，重试不丢业务身份 |
| 导出 | 指定数据、分辨率和几何正确，必要时回读 |

分别核验各 revision 的覆盖范围；`presentationRevision` 不能代替全部场景版本。状态和几何契约见根 `AGENTS.md` 第 10.4 节。

## 9. Feature 真实业务测试矩阵

本节条款见以下子节。

### 9.1. 共同链路


### 9.2. 专项断言

| 能力 | 核验重点 |
| --- | --- |
| OrthogonalCrop | 区分显示裁切、分析范围和体素派生；核验边界、有效区、复位和切换 |
| GapAnalysis | 实际 kernel/runtime、承诺字段、空与异常结果、身份及退出 |
| 分割与零件 | 前景/背景、连通关系、区域映射及真实拆分/合并语义 |

覆盖实际动作的正常、合法空结果、非法输入或缺资源、重复调用和退出；涉及数据写入、异步、View 或 runtime 时追加对应专项。异常可在受控副本或私有边界注入；它只证明异常处理。等值面显示、显隐或渲染位移不能冒充表面精度、分割修改或未承诺计量能力。

## 10. 生命周期、线程、异步与回调

本节条款见以下子节。

### 10.1. 生命周期矩阵

| 场景 | 核验重点 |
| --- | --- |
| 未 Attach 或未启动即请求 | 按契约拒绝，无半注册或意外后续执行 |
| Attach 成功、重复和部分失败 | ID、端口正确；无重复注册；已完成步骤反序回滚 |
| 正常、忙、队列满和重复请求 | 接纳与拒绝明确，任务有界，无静默丢失 |
| Exit/Detach/Stop | 幂等或明确拒绝，只清理自身资源 |
| 退出失败或 Stop/Detach 等待期限到期 | 保留可重试状态，不释放任务仍在使用的对象；期限见根 `AGENTS.md` 第 10.3 节 |
| 成功退出、析构和迟到结果 | 无失效访问、遗留回调、悬空捕获或跨 Session 污染 |

### 10.2. 按接口族验证回调

回调契约见 `FEATURE_DEVELOPMENT.md` 第 6.2.1 节，测试分别覆盖同步拒绝、已接纳完成、同步完成、空 callback、异常和重入。

admission 风格拒绝是否同步回调按端口声明；`SendRequestResult` 包装在有效 callback 下同步拒绝也完成一次。已接纳请求成功、失败或取消恰好完成一次，不排入二次完成。

### 10.3. 必测交错与重入

- 在读取、计算、候选构建和提交前取消，以及取消与完成竞争。

- A 计算时加载 B、改变依赖、退出 Feature 或销毁 Session；A 不能覆盖新状态。

- callback 内查询、再请求、取消或退出；按契约执行或明确拒绝。

- dispatcher 拒绝、延迟或抛异常；核验回调、VTK 写入和销毁线程。

- 连续请求和积压；核验队列、合并/拒绝策略及 tick 工作量。

调用 callback 前状态已提交，返回后重新核验对象和版本；同线程不等于重入安全，取消接纳也不等于任务已结束。

## 11. 渲染、交互与多 Feature 隔离

本节条款见以下子节。

### 11.1. View、输入与 Overlay

| 场景 | 核验重点 |
| --- | --- |
| 指定 View、缺失 ID、role 或 lease 错误 | 明确目标和失败，不回退到任意 renderer |
| 多 View 部分失败 | 反序回滚，不影响已有 View |

### 11.2. 质量档与 GPU 资源

覆盖实际策略的成功、资源不足、上传/物化失败、取消和恢复。资源顺序按根 `AGENTS.md` 第 10.5 节，Volume 与 Iso 分别核验，不要求新旧 GPU 资源同时常驻。

比较指定目标与实际 dimensions、质量和精度，确认计算与导出没有读取显示 LOD。显示失败与业务失败分别判定；资源拒绝条件按 `FEATURE_DEVELOPMENT.md` 第 9.2 节核验。

固定数据、相机、传递函数、窗口、质量和 View。图像容差预先确定，必要时截图并检查状态；截图不能证明完整数值和生命周期，频繁采集也不能扰动正常渲染。

### 11.3. 多 Feature 组合

由应用显式组合实际 Feature，覆盖共享数据更新、操作顺序、活动任务切换、取消、分别 Detach 和整体 Stop。架构只支持互斥时，验证明确拒绝。检查 input、overlay/effect、结果、快照、缓存、任务和释放互不污染。两两通过不能替代已知高风险完整组合；Qt 宿主的 UI 和部署仍由接收方负责。

### 12.2. 指标与测量口径

| 指标 | 边界与注意事项 |
| --- | --- |
| 初始化、首次可交互 | 区分数据 active、正确首帧和可处理输入，报告实际质量 |
| 接纳延迟 | 公共调用到同步接纳/拒绝，不等于业务完成 |

| 交互与显示 | 帧耗时、尾延迟、停顿与切换；区分 CPU Render、GPU 完成和实际呈现 |
| 取消与清理 | 接纳、任务退出、终态和临时资源收敛分别测 |
| 内存与显存 | 指标、进程/设备范围、基数、窗口和采样方式；预算不能替代实测 |
| 稳定性与质量 | 实际序列、次数/时长、失败数、稳定检查点趋势，以及数值、几何和身份 |

进程 CPU 时间与墙钟时间分开，嵌套或并行阶段不能相加当独占占比；Working Set 与私有提交也不能相加。热点诊断再补调用栈、等待、复制和线程证据。

测试器准备、参考核验和报告写出单列，产品入口自身校验计入总时延。说明采样开销和漏短峰限制，不扣除未经测定的资源估计。

## 13. 失败注入与私有 runtime

本节条款见以下子节。

### 13.1. 失败注入原则

为可能破坏状态的步骤核验失败返回、资源 owner、旧 active 和重试路径。注入可定位、可复现且有界，并确认命中目标失败点。预期拒绝且错误、状态、清理正确的负例可通过；缺编译器或输入未加载造成的偶然失败不算目标负例。

### 13.2. runtime 测试矩阵

仅对本次涉及且具有相应私有 runtime 的 Feature 执行下表。

| 场景 | 核验重点 |
| --- | --- |
| Debug/Release 正常业务 | 对应批准 bridge/runtime 实际加载，真实结果正确 |
| 缺 bridge 或 vendor DLL | 明确错误，无半加载或旧结果伪成功 |
| 错配置、架构或显式目录 | 正确拒绝，不从 PATH、当前目录或另一配置回退 |
| 来源混用、vendor 错误或非法输出 | 目录/版本约束和 shape/count/label/header 校验正确 |
| 失败、取消、退出后重试 | 句柄、任务和 active 一致，无悬空访问 |
| 公共边界 | vendor 头、类型、导入库和内部 target 不传播 |

只破坏受控测试副本，不改共享依赖或正式安装；结束后恢复环境，把必要证据写进测试报告或任务记录（记录方式见 `LOOP.md`）。mock DLL 与真实 DLL 分开统计。
