## 2. 工作树

本节条款见以下子节。

### 2.1. 目录与创建

```text
<repoParent>/MVVCVTK/                         # 主工作树，停在主分支
<repoParent>/MVVCVTK-worktrees/<branchKey>/   # 每个开发或实验分支一个工作树
```

通用定义见 core/GIT_WORKFLOW.core.md 第 2.1 节。

- **baseline 执行例外**：构建新的 SDK 发布包（发行）和合并本身在 baseline 树中进行；合并本身包括合并后在目标树重新 configure 以同步解决方案。合并后的构建、测试与业务验证仍使用派生工作树。

**不使用系统盘**：

- 工作树：任何工作树（开发、实验、测试验证）都不能建在系统盘（以当前环境识别结果为准）上，`<repoParent>` 必须位于非系统盘。
- 仓库外任务产物：clean-room、stage、构建输出、临时文件和日志也必须位于非系统盘。
- 工具自身数据例外：系统盘上只允许存在工具自身的安装、配置和会话数据（例如会话工具的用户目录），它们不属于任务产物。

- `<worktreePath>` 是创建前解析好的绝对路径，取 `<repoParent>/MVVCVTK-worktrees/<branchKey>`，不依赖 shell 当前目录。

### 2.3. 构建隔离

本项目的构建隔离对象按下表逐项核对；本表只列项目对象，隔离动作仍见下文转接的 core 定义，位置范围见本文件第 2.1 节“不使用系统盘”。

| 隔离对象 | 核对项 |
| --- | --- |
| 构建目录 | `binaryDir` |
| 生成文件 | 生成头 |

通用定义见 core/GIT_WORKFLOW.core.md 第 2.3 节。

- **临时文件留在工作树内**：执行构建、测试和脚本前，把 `TEMP` 和 `TMP` 指向本工作树的 `out/tmp`（不存在就先创建），让 CMake、MSBuild、CTest 等工具的临时文件不写到系统盘。

### 6.7. 过时 SDK、构建与对应输出

- **先核实来源**：核对对应工作树当前 `HEAD`、产物记录的源码提交及所属工作树和任务；SDK 来源核验按 `SDK_DELIVERY.md` 第 10.2、11.4、12.8 节执行，不能仅凭修改时间或目录名判定过时。

- **清理门槛**：`<artifact-source>` 是已核实的产物源码提交 SHA。在对应工作树先用 `git merge-base --is-ancestor "<artifact-source>" HEAD` 确认祖先关系，再用 `git rev-list --count "<artifact-source>..HEAD"` 核对落后提交数。落后至少 15 个提交（`>=15`）时按本条清理；不足 15 个提交不因本条触发删除。来源分叉、非祖先或无法确认时先核实，不直接判为达到门槛。其他已有的任务完成清理条件仍然有效。

- **清理范围**：达到门槛后，清理该来源的 SDK（含对应包）、构建目录及能确认归属于该构建或 SDK 的输出，覆盖 `out/` 或约定的其他构建、包及输出位置。不得扫删整个 `out/`，不得删除其他工作树、任务或正式交付仍需保留的产物。

- **沿用删除约束**：清理前核对具体路径、归属和占用，保留共享输入及必要证据，按第 6.3、6.4、6.6 节、`TESTING.md` 第 16.4 节及根 `AGENTS.md` 第 6、14 节的适用约束执行。本条不扩大通用删除授权。
